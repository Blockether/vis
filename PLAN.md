# PLAN — Speak with a chosen engine and a chosen voice, on upstream sherpa-onnx

*Speech out is an engine registry, exactly like speech in — and nothing copyleft ships inside the binary.*

### The root problem

Every question worth asking about spoken replies — which engine, which voice, on the device or on
the gateway — is a question the registry already answers for transcription and that nothing can ask
for synthesis. And the single speech binary we do ship carries a copyleft phonemizer we neither
need nor advertise.

### What we solve

Upstream sherpa 1.13.5 with no ONNX Runtime pin; a `speech` registry that is the mirror image of
`voice`; pocket-tts as the first gateway engine, converted by us from the original weights, with
voices we chose and may redistribute; the device engines (Siri on iOS, Android TTS) promoted from
an implementation detail to one engine choice among several; Piper kept as an engine the user can
opt into without us shipping GPL-3; and one manifest that states, per artifact, the license under
which we redistribute it.

### What we do not solve

Streaming token-level synthesis (the projection is a finished block); a voice-cloning UI; replacing
Parakeet — CC BY 4.0 permits commercial use, so it stays and earns an attribution line; new
platforms beyond the five the native artifacts cover.

### Alternatives considered

- **Stay on `com.litongjava/sherpa-onnx-java-api`** — two minors behind, has no pocket/supertonic
  family at all, forces the ORT ABI pin and its 90-line loader workaround, and the sherpa
  maintainer answered issue #143 by pointing at JitPack.
- **Vendor the jars in the repo** — four platforms of native blobs in git to avoid one
  `:mvn/repos` line.
- **Take `KevinAHM/pocket-tts-onnx` as the model** — a third-party derivative whose own terms are
  not stated; converting from the CC BY 4.0 originals keeps the provenance one hop and the
  attribution correct. Its `tokenizer.model` is only what upstream's script reads, and the same
  file exists in the original weights.
- **Kokoro (Apache-2.0) as the first engine** — the best-licensed weights, but sherpa's Kokoro path
  wants `lexicon.txt` plus espeak-ng-data for out-of-vocabulary words: GPL-3 data on top of a
  GPL-3-linked binary. It joins Phase 7, not Phase 4.
- **Supertonic** — OpenRAIL adds use-based restrictions; not a commercially clean license by this
  repository's rule.
- **Ship upstream's TTS natives as they are** — that is the espeak-ng problem, unchanged and now
  deliberate.
- **A cloud TTS API** — the projection must work offline, at no per-word cost, on a gateway a user
  runs; the app already speaks with no network.

## Phase 1 — Take upstream sherpa-onnx v1.13.5 and delete the ONNX Runtime pin

**Rationale.** Without it we stay on a repackaged 1.12.7 that has no pocket family to build on,
every ASR start pays `ensure-onnxruntime-native!` to satisfy a pin that only exists because that
fork's JNI was built against ORT 1.17.1, and the native image carries an 83.5 MB dependency whose
payload already sits inside the artifact we are about to fetch.

**Data.** None. A dependency swap and a deletion; no shape crosses a boundary.

**Acceptance criteria.**
- `extensions/common/vis-foundation-voice/deps.edn` — `:mvn/repos {"jitpack" {:url "https://jitpack.io"}}`,
  `com.github.k2-fsa.sherpa-onnx/sherpa-onnx-jvm {:mvn/version "v1.13.5"}` and the host's
  `sherpa-onnx-native-lib-<platform>`; both `com.litongjava/...` and `com.microsoft.onnxruntime` gone.
- `extensions/common/vis-foundation-voice/src/com/blockether/vis/ext/foundation_voice/asr.clj` —
  `onnxruntime-version`, `onnxruntime-resource-name`, `onnxruntime-target-names`,
  `ensure-onnxruntime-native!` and its call at `:385` deleted; the loader now finds both dylibs in
  one directory.
- The `onnxruntime-abi-test` that guarded the pin is deleted with it.
- `build.clj:1275` — the `ai/onnxruntime/native/...` include drops; `:1041` and `:1091`
  docstrings stop naming a dependency we no longer have.
- Test that proves it done: the extension's existing ASR round-trip transcribes a fixture WAV on
  1.13.5, run through `run_tests` on the extension path.

**Unknowns.**
- Does JitPack's first resolution of a coordinate this repository has never fetched block CI while
  it builds, and does the build need a warm `~/.m2` step?
- Do all five platform artifacts we ship carry ONNX Runtime the way `osx-aarch64` does, or does one
  of them still need a copy step?

## Phase 2 — Widen `internal/voice.clj` to carry BOTH directions

**Rationale.** Voice is one subject with two directions, and a second namespace would fork every
answer to the same question: which engines exist, which is default, is its model downloaded, where
did that job go. `voice.clj` already answers all four for transcription behind an engine registry —
one `register-engine!`, one job store, one readiness machine, one feature toggle — so synthesis
belongs in it, keyed by direction, not in a twin that drifts. Without it every surface that wants a
spoken reply has to know which engine exists and whether its model is downloaded, and "choose your
engine" stays a code change instead of a configuration question.

**Data.** None. Every function here is in-process; the shapes it hands out cross the wire in
Phase 3 and are specified there.

**Acceptance criteria.**
- `src/com/blockether/vis/internal/voice.clj` — the registry keyed by DIRECTION, `:transcribe` and
  `:synthesize`: `register-engine!` / `unregister-engine!` / `set-default-engine!` / `engines` /
  `engine` / `default-engine` / `resolve-engine` take a direction and neither side can resolve the
  other's default; `VIS_VOICE_ENGINE` is joined by `VIS_SPEECH_ENGINE`; `readiness` / `prepare!` /
  `ready?` and the TTL-capped job store with `watch!` serve both. New for synthesis: `voices`,
  `synthesize!`, and `phases` growing `:synthesizing`. Definitions ordered so nothing is
  forward-declared.
- The `speech` feature toggle registered from merged config so `/reload` respects a project override.
- Test that proves it done: `test/com/blockether/vis/internal/voice_test.clj` registers a fake
  synthesis engine beside a transcription one, proves each direction resolves only its own default
  by pin and by environment variable, drives one synthesis job to `done` and one to `failed`, and
  proves the TTL sweep drops a finished job.

**Unknowns.**
- Does a synthesis job need a `:queued` phase when two turns finish at once, or is one job per
  request with a bounded pool enough?
- Can one engine serve both directions, or is a registry entry always exactly one direction?

## Phase 3 — Serve speech over HTTP and advertise it

**Rationale.** Until the capability is negotiated, every client has to guess; `features.voice` is
how the app already learns that transcription exists (`SessionScreen.tsx:1372`, `:2570`), and the
speech picker in Phase 6 has nothing to populate without the engine and voice catalogue.

**Data.** The job, the voice and the capability block cross the wire. Wire keys are snake_case
strings and booleans are `is_<foo>`, rendered by `wire/->wire`.

```clojure
(s/def :vis.speech/id string?)                 ;; engine id, e.g. "pocket-tts", "device"
(s/def :vis.speech/label string?)
(s/def :vis.speech/is-default boolean?)
(s/def :vis.speech/voice-id string?)
(s/def :vis.speech/language string?)           ;; BCP-47
(s/def :vis.speech/license string?)            ;; SPDX id the voice is redistributed under
(s/def :vis.speech/is-commercial-ok boolean?)
(s/def :vis.speech/voice
  (s/keys :req-un [:vis.speech/voice-id :vis.speech/label :vis.speech/language
                   :vis.speech/license :vis.speech/is-commercial-ok]))
(s/def :vis.speech/voices (s/coll-of :vis.speech/voice :kind vector?))
(s/def :vis.speech/engine
  (s/keys :req-un [:vis.speech/id :vis.speech/label :vis.speech/is-default :vis.speech/voices]))
(s/def :vis.speech/status #{"ready" "downloading" "unavailable" "failed"})
(s/def :vis.speech/phase #{"preparing" "synthesizing" "done" "failed"})
(s/def :vis.speech/progress (s/int-in 0 101))
(s/def :vis.speech/job-id string?)
(s/def :vis.speech/sample-rate pos-int?)
(s/def :vis.speech/job
  (s/keys :req-un [:vis.speech/job-id :vis.speech/phase :vis.speech/progress]
          :opt-un [:vis.speech/error :vis.speech/audio-url :vis.speech/sample-rate
                   :vis.speech/duration-ms]))
(s/def :vis.speech/capabilities
  (s/keys :req-un [:vis.speech/is-enabled :vis.speech/engines :vis.speech/phases
                   :vis.speech/status]))
```

**Acceptance criteria.**
- `src/com/blockether/vis/internal/gateway/server.clj` — `with-speech-engine` beside
  `with-voice-engine` (`:2645`); `POST /v1/sessions/:sid/speech` returning `audio/wav` for short
  text and a job for long; `GET|POST /v1/sessions/:sid/speech/model`;
  `GET|DELETE /v1/sessions/:sid/speech/jobs/:job-id`; `GET .../speech/jobs/:job-id/events` (SSE);
  `GET .../speech/jobs/:job-id/audio`; `:speech` added to `:features` at `:2902`.
- `src/com/blockether/vis/internal/gateway/wire.clj` — `speech-job-event` beside `voice-job-event`
  (used at `server.clj:2882`).
- Test that proves it done: a fake engine registered, `POST …/speech` answers RIFF/WAVE magic with
  the right content type, a long body answers a job whose SSE stream reaches `done` and whose audio
  route serves the same bytes, and `/v1/capabilities` reports the engine, its voices and the phase
  vocabulary.

**Unknowns.**
- Should the short-text threshold be characters or an estimated duration, and does the app ever
  want the WAV inline in the SSE terminal frame?

## Phase 4 — `tts.clj` in `vis-foundation-voice`: pocket-tts on sherpa, with voices we own

**Rationale.** Pocket is the only family in 1.13.5 whose config carries no lexicon and no data
directory, so it is the only one that speaks without a phonemizer; and because its voice is an
embedding of a reference clip rather than a baked speaker table, the voice catalogue is ours to
choose rather than the model author's to license. Without this phase the registry has no engine and
the gateway still cannot speak.

**Data.** None. The engine's voice descriptors are the Phase 3 shape; the model files never leave
the extension.

**Acceptance criteria.**
- `extensions/common/vis-foundation-voice/src/com/blockether/vis/ext/foundation_voice/tts.clj` —
  beside `asr.clj`, on the native `sherpa.clj` already provisions, registering one `:synthesize`
  engine through `voice/register-engine!`. `OfflineTts` + `OfflineTtsPocketModelConfig`; download,
  verify and atomically install into `~/.vis/models/...` through `files.clj` in the shape
  `install-model!` already proves, with the same notification and readiness phases the app renders
  for ASR.
- `voices.edn` — one entry per shipped voice: id, label, language, source URL, SPDX id,
  `is-commercial-ok`. It ships the catalogue voices that are CC0 or CC BY 4.0; **`cosette`
  (Expresso) and `jean` (EARS) are CC BY-NC and are never converted**, and `rafael`/`juergen` wait
  on provenance.
- The engine picks a language checkpoint as well as a voice — `english` is fetched first and the
  `*_24l` variants are registered but not downloaded until one is asked for.
- Test that proves it done: synthesize one sentence with a fixture voice, assert a non-silent PCM
  body at the sample rate the model declares, and assert the engine reports `unavailable` with an
  actionable message when the model directory is absent.

**Unknowns.**
- Provenance of `rafael` (`g-Vi8PgmSY0-enhanced-v2.wav`, a YouTube id) and `juergen`
  (`de-DE-juergen.mp3`). Both arrived undocumented on an `add_lang_not_documented` branch and the
  voices README does not cover them; until Kyutai answers they stay out of the manifest.
- How many seconds does a stable embedding need, and does int8 (98.3 MB) hold quality against fp32
  (168.1 MB) for a three-second clip?

## Phase 5 — Publish models and natives from our own release, with a manifest a test enforces

**Rationale.** A first ASR run today downloads 465 MB from a URL we do not own (`asr.clj:24`), and
nothing anywhere records what license any artifact carries — so nothing stops a non-commercial
voice or an espeak-carrying native from arriving by accident. Converting pocket-tts ourselves is
also what makes its weights ours to serve rather than a third party's export to trust.

**Data.** The manifest is read by every downloader and is the answer to "may we redistribute this".

```clojure
(s/def :vis.model/id string?)
(s/def :vis.model/url string?)                  ;; where Vis fetches it
(s/def :vis.model/sha256 (s/and string? #(re-matches #"[0-9a-f]{64}" %)))
(s/def :vis.model/bytes pos-int?)
(s/def :vis.model/license string?)              ;; SPDX id
(s/def :vis.model/attribution string?)          ;; the line reproduced in NOTICE
(s/def :vis.model/source-url string?)           ;; where it came from originally
(s/def :vis.model/is-commercial-ok true?)       ;; never false: such an artifact is not listed
(s/def :vis.model/is-redistributed boolean?)    ;; false = fetched from upstream, never re-hosted
(s/def :vis.model/entry
  (s/keys :req-un [:vis.model/id :vis.model/url :vis.model/sha256 :vis.model/bytes
                   :vis.model/license :vis.model/attribution :vis.model/source-url
                   :vis.model/is-commercial-ok :vis.model/is-redistributed]))
(s/def :vis.model/manifest (s/coll-of :vis.model/entry :kind vector? :min-count 1))
```

**Acceptance criteria.**
- `resources/vis-models/manifest.edn` — one entry per artifact; `asr.clj` and the Phase 4 engine
  read their URL and checksum from it instead of a literal.
- `scripts/convert-pocket-tts.py` — our export from the original CC BY 4.0 weights, reusing
  upstream's `convert_tokenizer.py` against the original `tokenizer.model`.
- A CI job building espeak-free natives: upstream plus a patch adding `SHERPA_ONNX_ENABLE_ESPEAK`
  (default ON, so the patch is upstreamable) and building with it OFF, published for the five
  platforms we ship.
- A `vis-models-<date>` release holding the converted pocket-tts, Parakeet and those natives;
  `THIRD_PARTY_MODELS.md` generated from the manifest.
- Test that proves it done: every model or native URL referenced anywhere in the tree is in the
  manifest; every entry has an SPDX id, an attribution line and `is-commercial-ok true`; every
  entry with `is-redistributed true` is on a host we control; and the built native for the host
  platform contains no `espeak-ng`, `phontab` or `phondata` marker.

**Unknowns.**
- Getting the weights at all: the gate is a one-time human click. Someone signed in to Hugging Face
  presses **Agree** once on `kyutai/pocket-tts`, after which a read-scoped `HF_TOKEN` lives in CI
  secrets and never in the tree.
- Do the espeak-free natives get built in this repository's CI or in a small sibling repository,
  given the native build's memory profile?

## Phase 6 — Let the app choose the engine and the voice

**Rationale.** `speech.ts:10` is device-only and `speechOutput.speak(text)` takes nothing but text,
so a gateway that can now speak is invisible, and an iPhone user cannot pick the Siri voice already
installed on the phone. Without this phase everything above is a capability nobody can reach.

**Data.** None. The request body and the capability block are Phase 3's shapes; the chosen engine
and voice are device-local settings.

**Acceptance criteria.**
- `apps/vis-companion/src/lib/speech.ts` — an output router over `off | device | gateway`, keeping
  `speechOutput.speak(text)` unchanged for `SessionScreen.tsx:2871` and `ChatContent.tsx:2202`.
- `apps/vis-companion/src/lib/speech-voices.ts` — device voices from `speechSynthesis.getVoices()`
  (Siri voices through WKWebView on iOS) and from `NativeSpeech.getVoices` on Android; gateway
  voices from `features.speech`.
- `apps/vis-companion/scripts/android-prepare.mjs:556-604` — `getVoices`, `setVoice` and `setRate`
  added to the generated `NativeSpeechPlugin`, idempotently; generated `android/` untouched.
- `apps/vis-companion/src/screens/SettingsScreen.tsx` — a **Spoken replies** control (Off / This
  device / Gateway) and a voice list, built only from the closed `ui.tsx` vocabulary; read
  `doc("companion-ui")` first.
- Test that proves it done: `lib/speech.test.ts` covers routing, voice selection and the fallback
  when the gateway engine answers `unavailable`, plus a settings layout test; `npm run lint` and
  `npm run build` green.

**Unknowns.**
- With the gateway engine selected and the gateway unreachable, does the app fall back to the
  device voice silently or stay quiet and show the composer notice?
- Is the choice per machine (a row in `components/Machines`) or once per device?

## Phase 7 — Piper and Kokoro as opt-in engines that never enter our binary

**Rationale.** Piper is hundreds of voices in dozens of languages and Kokoro is the best-licensed
weights available, but both phonemize through espeak-ng, and `build.clj:1274` bakes natives into an
Apache-2.0 image. Without this phase we either ship copyleft or lose the voices — this is the only
phase where a GPL-3 artifact is allowed to exist, on the user's own disk, fetched by the user.

**Data.** None. The engines register into Phase 2's registry and describe themselves with Phase 3's
shapes.

**Acceptance criteria.**
- The Piper and Kokoro engines register only when an upstream native is already present under
  `~/.vis/native/...`; the fetch is an explicit command, never automatic, and its manifest entries
  carry `is-redistributed false` with the upstream URL.
- A per-voice allowlist in the manifest: `rhasspy/piper-voices` is MIT at the repository level while
  individual voices inherit their training data's terms, so a voice enters the catalogue only with
  its own SPDX id and `is-commercial-ok true`.
- Test that proves it done: with no native present the engine reports `unavailable` with the exact
  command to install it, and the Phase 5 license test still passes — no artifact we host carries an
  espeak marker.

**Unknowns.**
- Does Kokoro's `lexicon.txt` path cover enough English to be useful with espeak absent, which
  would make it a redistributable engine after all?

  `HF_TOKEN` and in no file in this tree.

Three decisions the plan takes, so they are not re-litigated in review:

1. **Commercial use is the bar; attribution is not a disqualifier.** CC BY 4.0 artifacts stay and
   earn a line in `THIRD_PARTY_MODELS.md` (Parakeet, pocket-tts). Non-commercial terms (Expresso
   voices), use-based restrictions (OpenRAIL, so Supertonic) and unstated third-party derivative
   terms are excluded. Copyleft is refused only where we would *distribute* it — hence Phase 7.
2. **Pocket-tts is the first gateway engine, not Kokoro.** It is the only family that needs no
   phonemizer, which is the whole reason espeak-ng is in the binary; its voices are reference clips
   we choose, so the voice catalogue's licensing is ours to state.
3. **We host what we redistribute.** Models and natives come from a Vis release with a checksum and
   an SPDX id in one manifest, and a test refuses any artifact that is not in it.
